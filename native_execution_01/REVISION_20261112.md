# PR4: exact refusal contract and temporal discrimination

| Object | Explicit definition | Domain and role |
| --- | --- | --- |
| Wrapper P | Ed25519 signature over PERMIT domain and canonical JSON body | Binds request, allocation, owner, grant, native epoch and validity interval |
| Deadline d | P.body.not_after, integer monotonic seconds | Exclusive upper bound at sampled validation |
| Sample t | checked_tick stored with permit consumption | Must satisfy not_before <= t < d |
| Native effect E | Application SQL change plus signed business result | Must commit or roll back with consumption |
| Consumption C | Unique challenge, wrapper digest, rid, result digest and t | Stored inside the same native transaction as E |

Motivation is internal: separate cryptographic rejection, binding rejection, ambiguous native outcomes and commit-time validity. No external novelty or production guarantee is claimed.

The historical run 43124669096 remains failed at ff42f6c47c854586b603205c104108312b6ba75c. Its original 40-cell artifact remains separately available as 13903056383. This revision adds 16 temporal cells and six isolated negative probes per live C cell. It does not reinterpret old captures using new sources or regenerate the old artifact.

The only refusal-semantic change is the exact mapping Refused('SIGNATURE') -> Refused('SIGNATURE_INVALID') in the new owner facade, retaining the exception cause. Shared frozen sources remain unchanged. Tests distinguish a signature bit flip, unsigned body mutation, validly signed wrong allocation, request mutation, foreign signer and wrong domain. The reader checks concrete witnesses, peer identity, exact refusal code, unchanged SQL stores and unchanged native-entry counters around each probe. Contract unit tests also ensure unrelated errors and HOLD_NATIVE are not relabelled.

For expiry or revocation inside FCI, wrapper failures are logged with stage and transaction context and re-raised. Native suppression into UNKNOWN remains visible. Exact refusal assertions remain obligations; an RPC success carrying HOLD_NATIVE is not effect admission or refusal proof.

Temporal instrumentation pauses in the existing trusted before_commit hook after the final sample and consumption insertion. The supervisor waits past d and either releases the owner or kills it by pidfd. Release is expected to expose the declared time gap; the kill variant must roll back both E and C. The supervisor timeline and SQL readback establish the fixture observation under trusted OS/root assumptions. They do not establish a bounded physical commit latency or an industrial clock guarantee. There is no new check after the pause; adding one would change the question under test.

Qualification requires all exact baseline assertions before mutations count toward reception. Both offline reader modes run and preserve a DIAGNOSTIC_ONLY report when baselines fail.
